# 큐브 솔버 인터페이스 정의서 (v1.0)

이 문서는 학생 솔버와 채점 시스템이 주고받는 데이터 형식과 호출 규약을 정의한다.
여기 적힌 것 외의 동작은 보장하지 않는다.

## 1. 큐브 상태 표현

- 길이 **54**의 정수 리스트. 각 원소는 그 위치(facelet)에 붙은 스티커의 색 (0~5).
- 색 번호 = 완성 상태에서 그 스티커가 속한 면 번호.
- 면 순서와 인덱스 범위

  | 면 | 번호 | 인덱스 |
  |---|---|---|
  | U (위) | 0 | 0 ~ 8 |
  | R (오른쪽) | 1 | 9 ~ 17 |
  | F (앞) | 2 | 18 ~ 26 |
  | D (아래) | 3 | 27 ~ 35 |
  | L (왼쪽) | 4 | 36 ~ 44 |
  | B (뒤) | 5 | 45 ~ 53 |

- 각 면 안에서는 **바깥에서 그 면을 바라봤을 때** 왼쪽 위 → 오른쪽 아래, 행 우선 순서.
- 전개도 (숫자는 인덱스)

```
                 |------------|
                 |  0   1   2 |
                 |  3   4   5 |      U
                 |  6   7   8 |
    |------------|------------|------------|------------|
    | 36  37  38 | 18  19  20 |  9  10  11 | 45  46  47 |
    | 39  40  41 | 21  22  23 | 12  13  14 | 48  49  50 |
    | 42  43  44 | 24  25  26 | 15  16  17 | 51  52  53 |
    |     L      |     F      |     R      |     B      |
                 |------------|
                 | 27  28  29 |
                 | 30  31  32 |      D
                 | 33  34  35 |
                 |------------|
```

- 완성 상태: `[0]*9 + [1]*9 + [2]*9 + [3]*9 + [4]*9 + [5]*9`
- 중심 스티커(인덱스 4, 13, 22, 31, 40, 49)는 항상 자기 면 색이다. 큐브 전체를 돌리는 회전(x, y, z)은 없다.
- 이 순서는 Kociemba facelet 표기(`UUUUUUUUURRR...`)와 같다. `cube.cube.to_facelet_string` 으로 변환할 수 있다.

## 2. 회전 표기

- Singmaster 표기, **18가지**만 허용한다.

  | 기호 | 뜻 |
  |---|---|
  | `U` `R` `F` `D` `L` `B` | 그 면을 바깥에서 봤을 때 시계 방향 90° |
  | `U'` `R'` `F'` `D'` `L'` `B'` | 반시계 방향 90° |
  | `U2` `R2` `F2` `D2` `L2` `B2` | 180° |

- 회전 수 계산은 **half-turn metric**: 어떤 기호든 1수로 센다 (`U2`도 1수).
- 허용되지 않은 문자열(`u`, `x`, `M`, `R3` 등)이 하나라도 있으면 그 문제는 실패.

## 3. 문제 세트 형식 (JSON)

```json
[
  {
    "problem_id": "d06-10-0003",
    "tier": "d06-10",
    "scramble_depth": 8,
    "state": [0, 5, 0, 3, 0, 1, ...]
  }
]
```

| 필드 | 설명 |
|---|---|
| `problem_id` | 문제 식별자 |
| `tier` | 난이도 구간. `d01-05`, `d06-10`, `d11-15`, `d16-20`, `random` |
| `scramble_depth` | 섞은 회전 수. `random` 구간은 `null` |
| `state` | 길이 54 정수 리스트 |
| `scramble` | (공개 세트에만 있음) 섞을 때 쓴 회전 목록. 채점 세트에는 없다 |

`random` 구간은 60수를 섞어 만든 사실상 완전 무작위 상태다.
`scramble_depth`는 최단 거리가 아니라 **섞은 횟수**이며 실제 최단 거리는 그보다 짧을 수 있다.

## 4. 솔버 호출 규약 (파이썬)

채점기는 제출 저장소의 `solver/solve.py` 에서 `Solver` 클래스를 불러온다.

```python
class Solver:
    def __init__(self, weights_dir: str, device: str):
        """weights_dir: 가중치 폴더 경로 (= 저장소의 solver/weights). device: "cpu" 또는 "cuda".
        모델 로딩 등 준비 작업. 한 번만 호출되고 소요 시간은 채점에서 제외된다 (상한 300초)."""

    def solve(self, state: list[int], time_limit: float) -> list[str]:
        """state: 길이 54 정수 리스트.  time_limit: 이 문제에 쓸 수 있는 초.
        반환: 회전 문자열 리스트. 적용하면 완성 상태가 되어야 한다. 풀지 못하면 [] 반환."""
```

규칙

- `solve`는 문제마다 순서대로 한 번씩 호출된다. 호출 사이에 상태를 저장해도 되지만 다른 문제의 정보를 쓰는 것은 의미가 없다 (문제는 독립이다).
- `state`를 수정해도 된다 (복사본이 전달된다).
- 반환값 검증은 **채점기 쪽 시뮬레이터**가 한다. 솔버가 "풀었다"고 해도 채점기가 적용해서 완성되지 않으면 실패다.
- 예외가 발생하면 그 문제는 실패이고 다음 문제로 넘어간다.
- `time_limit`을 넘겨도 응답이 없으면 프로세스를 강제 종료하고 다시 띄운다. 그 문제는 실패다.

## 5. 제한 사항

| 항목 | 값 |
|---|---|
| 문제당 제한 시간 | 30초 (CPU 기준, 채점 서버 공지 참고) |
| 해법 최대 길이 | 60수 |
| 가중치 폴더 용량 | 100 MB 이하 |
| 허용 패키지 | `torch`, `numpy` 및 파이썬 표준 라이브러리 |
| 금지 | 네트워크 접근, 고전 큐브 솔버 라이브러리 호출(kociemba, rubik-solver 등), 추론 시 외부 프로세스 실행 |
| 실행 환경 | Python 3.11, PyTorch 2.x CPU (Docker 이미지 `cube-grader`), 메모리 4 GB |

- 고전 솔버는 **학습 데이터 생성에는 사용해도 된다.** 추론 코드(`solver/`)에서 호출하면 0점 처리된다.
- 가중치 파일에 조회표(lookup table)를 넣어 탐색을 대신하는 것은 딥러닝 사용으로 인정하지 않는다.

## 7. 점수 계산

구간별 점수 = 가중치 × 해결률 × (0.6 + 0.4 × 회전 수 효율)

- 회전 수 효율 = 해결한 문제의 `min(1, 기준 길이 / 해법 길이)` 평균. 기준 길이는 `scramble_depth`, `random` 구간은 20.
- 가중치: d01-05 = 10, d06-10 = 20, d11-15 = 25, d16-20 = 25, random = 20 (합 100).
- 탐색 폭만 키워도 해결률은 오르지만 해법이 길어진다. 짧은 해법은 휴리스틱(모델)이 정확해야 나온다. 효율 비중이 큰 이유다.
- 이 수치는 `cube/evaluate.py` 의 `DEFAULT_CONFIG` 에 있으며 교수자가 공지로 바꿀 수 있다.

## 8. 저장소 구조 (제출물)

```
<repo>/
  cube/            # 시뮬레이터와 채점기. 수정 금지 (채점 시 교수자 버전으로 교체됨)
  solver/          # 학생 작업 영역. 채점 서버는 이 폴더만 가져간다
    __init__.py
    solve.py       # Solver 클래스 (필수)
    model.py       # 모델 정의
    train.py       # 학습 스크립트
    weights/       # 가중치 (필수, 100 MB 이하)
  data/public_problems.json   # 공개 문제 세트
  scripts/check_submission.py # 제출 전 자가 검사
  REPORT.md        # 보고서 (필수)
```
