# 중간보고 발표 안내

Deep Cube Challenge 2026 팀 프로젝트의 중간 점검입니다. 완성도가 아니라 **지금까지 무엇을 바꿨고, 그 결과가 어떤지, 남은 기간에 무엇을 할지**를 봅니다.

- 발표일: **2026년 11월 18일(수)** 수업 시간
- 형식: PPT, 팀당 **발표 10분 + 질의 3분**
- 발표자: **팀장 1명**이 발표. 질의는 팀원 전원에게 합니다
- 제출: **11월 17일(화) 23:59**까지 팀 저장소 `docs/midterm/` 에 PPT 파일 push (`팀명_중간보고.pptx`). PDF 도 함께 넣으면 좋습니다.

## 발표 구성 (8장 안팎)

| # | 장표 | 들어갈 내용 |
|---|---|---|
| 1 | 팀 소개와 역할 | 팀원별 맡은 부분과 지금까지 각자 한 일 한 줄씩 |
| 2 | 문제 이해 | 상태 표현, 평가 방식, 점수식을 **팀의 말로** 설명 |
| 3 | 기본 코드 진단 | 템플릿 그대로 돌린 공개 세트 결과표와 "왜 6수부터 무너지는가"에 대한 팀의 분석. 모델 문제인지 탐색 문제인지 |
| 4 | 접근 방법 | 기본 코드와 **무엇이 다른가**를 그림 한 장으로. 모델·데이터·탐색 중 어디를 바꿨고 왜 그 선택인지 |
| 5 | 현재 결과 | 공개 세트 구간별 해결률과 평균 회전 수. **첫 행은 기본 코드 결과**, 그 아래 팀의 결과 |
| 6 | 실험 기록 | 시도했다가 버린 것 포함. 무엇을 바꿨더니 얼마나 달라졌는지 표 하나 |
| 7 | 어려운 점과 남은 계획 | 막힌 부분, 마감까지 주 단위 계획, 교수에게 묻고 싶은 것 |
| 8 | 시연 | 자가 검사(`scripts/check_submission.py`) 통과 화면이나 Colab 실행 캡처 한 장. 영상이면 30초 이내 |

## 지켜야 할 것

- **결과표는 채점 스크립트 출력을 그대로 캡처**해서 넣습니다. 직접 만든 표는 인정하지 않습니다.
  ```bash
  python -m cube.evaluate --problems data/public_problems.json
  ```
- 3번과 5번에는 **기본 코드(템플릿 그대로)의 결과**가 반드시 들어갑니다. 기말 보고서의 애블레이션 첫 행이 됩니다.
- 결과를 낸 커밋 해시를 5번 장표에 적습니다. 저장소에서 재현할 수 있어야 합니다.
- 실패한 시도를 적는 것은 감점이 아닙니다. 무엇을 해 봤고 왜 안 됐는지가 오히려 평가 대상입니다.
- 참고한 자료와 생성형 AI 사용 내역은 마지막 장에 적습니다 (기말 보고서와 같은 기준).

## 평가에서 보는 것

1. 기본 코드를 넘어선 **자기 설계**가 있는가. 하이퍼파라미터만 바꾼 팀은 4번 장표가 비어 보입니다.
2. 결과가 **재현 가능한 형태**로 제시되는가 (채점 스크립트 출력 + 커밋 해시).
3. 남은 계획이 **현실적**인가. 마감까지 남은 주 수에 맞는지 봅니다.
4. 팀원 모두가 자기 부분을 설명할 수 있는가. 질의는 팀장이 아닌 팀원에게도 합니다.

중간보고는 발표·시연 평가의 일부로 반영됩니다. 질문은 팀 저장소 Issues 에 남겨 주세요.
