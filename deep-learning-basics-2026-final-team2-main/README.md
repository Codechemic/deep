# 딥러닝 기초 기말 과제: 딥러닝으로 3×3×3 큐브 풀기

섞인 큐브 상태를 입력받아 완성까지의 회전 목록을 출력하는 솔버를 만든다.
핵심은 **신경망이 학습한 것으로 탐색을 이끄는 것**이다. 고전 큐브 알고리즘을 그대로 호출하는 것은 과제가 아니다.

## 1. 시작하기

```bash
git clone <팀 저장소 URL>
cd <저장소>
pip install -r requirements.txt      # Colab 은 torch 가 있으므로 생략 가능
python -m pytest tests -q            # 시뮬레이터 검사
python -m solver.train --steps 1000 --batch 512 --device cuda    # 기본 모델 학습 (1분 안팎)
python -m cube.evaluate --problems data/public_problems.json     # 공개 문제로 채점
python scripts/check_submission.py   # 제출 전 자가 검사
```

Colab 에서는 저장소를 clone 한 뒤 `%cd <저장소>` 로 들어가서 위 명령을 `!` 를 붙여 실행하면 된다.
학습 중간 결과는 구글 드라이브에 저장할 것. Colab 세션은 예고 없이 끊긴다.

## 2. 저장소 구조

| 경로 | 역할 | 수정 |
|---|---|---|
| `cube/cube.py` | 시뮬레이터. 상태 표현, 18가지 회전, one-hot 변환 | 금지 |
| `cube/scramble.py` | 스크램블 생성, 문제 세트 생성 | 금지 |
| `cube/evaluate.py` | 채점기. 교수자 서버와 같은 코드 | 금지 |
| `solver/solve.py` | **Solver 클래스.** 채점기가 호출하는 유일한 진입점 | 자유 |
| `solver/model.py` | 모델 정의 | 자유 |
| `solver/train.py` | 학습 스크립트 | 자유 |
| `solver/weights/` | 학습된 가중치. 100 MB 이하 | 필수 |
| `data/public_problems.json` | 공개 문제 100개 (구간별 20개, 스크램블 포함) | 금지 |
| `REPORT.md` | 보고서 | 필수 |

`cube/` 는 채점 때 교수자 버전으로 교체되므로 고쳐도 반영되지 않는다. 채점 서버는 `solver/` 폴더만 가져간다.
따라서 솔버가 쓰는 코드는 전부 `solver/` 안에 있어야 한다.

## 3. 기본 코드가 하는 일

1. `solver/train.py`: 완성 상태에서 d번 섞은 상태를 만들고 d 를 라벨로 "남은 회전 수" 를 예측하는 작은 MLP 를 학습한다.
2. `solver/solve.py`: 18가지 회전을 적용해 본 뒤 모델 예측값이 가장 작은 상태로 한 수씩 전진한다 (탐욕 탐색).

이 기본 코드는 **일부러 약하게** 만든 것이다. 돌아가는 파이프라인의 예시이지 출발점으로 삼으라는 답이 아니다.
공개 세트에서 15점 안팎이 나오고, 학습을 더 오래 시켜도 거의 오르지 않는다. 얕은 문제는 풀지만 6수 이상 섞인 문제부터 무너진다.
모델과 탐색 중 어느 쪽이 병목인지 찾고, 둘 다 자기 설계로 바꾸는 것이 과제다. `solver/` 는 통째로 다시 써도 된다.
지켜야 할 것은 [INTERFACE.md](INTERFACE.md) 의 `Solver` 계약뿐이다.

## 4. 개선 방향 예시

난이도 순. 어디까지 갈지는 팀이 정한다.

- 학습 샘플 수와 모델 크기를 늘린다. (가장 쉬움. 하지만 한계가 금방 온다)
- 탐색을 바꾼다: 한 수씩 고르는 탐욕 탐색은 한 번 잘못 가면 돌아오지 못한다. 여러 후보를 동시에 유지하는 탐색(빔 서치, A* 변형 등)을 설계한다.
- 라벨 노이즈를 줄인다: 섞은 횟수는 최단 거리의 상한일 뿐이다. 더 정확한 라벨을 만들 방법을 찾는다.
- 외부 솔버(kociemba 등)로 (상태, 다음 회전) 쌍을 만들어 **정책 모델**을 모방학습한다. 학습 데이터 생성에 외부 솔버를 쓰는 것은 허용된다.
- 가치 반복(DeepCubeA 의 approximate value iteration)으로 라벨을 자기 자신의 예측으로 갱신한다.
- 커리큘럼: 얕은 깊이부터 점차 깊게 학습한다.
- 탐색 개선: 예측 분산을 이용한 가지치기, 역방향 탐색과의 결합 등.

## 5. 채점

- 비공개 문제 세트(구간별 분포는 공개 세트와 같음)로 교수자 서버에서 채점한다.
- 지표: 구간별 해결률(1순위), 회전 수 효율(2순위). 응답 시간은 문제당 30초 상한만 적용한다.
- 점수식은 [INTERFACE.md](INTERFACE.md) 7절. 리더보드는 매일 자정 갱신한다.
- 최종 점수는 마감 시각의 `main` 브랜치 마지막 커밋으로 확정한다.
- 과제는 **팀 단위**로 제출한다. 팀 인원수와 전공에 관계없이 과제 내용과 평가 기준은 모든 팀에 같다. 역할 분담은 팀이 정한다.
- 성적 반영 비율(자동 채점 / 보고서 / 발표·시연)과 일정은 수업 공지를 따른다.
- 보고서와 발표에서는 **기본 코드와 무엇이 어떻게 다른지**를 본다. 하이퍼파라미터만 바꾼 제출은 자동 채점 점수가 높아도 보고서·발표 점수를 낮게 받는다.

## 6. 규칙

- 추론 코드에서 고전 큐브 솔버 호출 금지. 네트워크 접근 금지. 허용 패키지는 `torch`, `numpy`, 표준 라이브러리.
- 가중치에 조회표를 넣어 탐색을 대신하는 것은 딥러닝 사용으로 인정하지 않는다.
- 참고한 코드, 논문, 생성형 AI 사용 내역은 보고서에 전부 적는다. 미기재 사용이 발견되면 부정행위.
- 다른 팀의 저장소를 복사한 것이 확인되면 양쪽 모두 0점.

## 7. 자주 하는 실수

- `solver/weights/` 를 `.gitignore` 에 넣어서 가중치가 안 올라감 → 푸시 후 GitHub 에서 파일이 보이는지 확인.
- Colab 최신 torch 로 저장한 가중치가 서버에서 안 열림 → `torch.save` 로 `state_dict` 만 저장하고, `weights_only` 로 열리는지 확인.
- 노트북(.ipynb)만 올리고 `.py` 모듈이 없음 → 채점기는 노트북을 실행하지 않는다.
- `solver/` 바깥의 파일을 import → 채점 서버에는 없다.
- 모델 로딩에 5분 이상 걸림 → 초기화 상한 300초를 넘기면 전부 실패.
